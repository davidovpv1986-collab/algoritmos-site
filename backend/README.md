# Backend — API сайта «Алгоритмос»

Отдельный API-сервис на Node.js + Express + TypeScript. Единственная задача —
безопасный приём заявок с формы сайта и их отправка **на почту компании**
(`MAIL_TO`, по умолчанию info@algorithmos.ru) через любой SMTP-ящик.

## Как уходят заявки

1. Форма сайта отправляет `POST /api/leads` (имя, email, **телефон**, задача).
2. Заявка проходит валидацию и антиспам-проверки.
3. Если настроен SMTP — уходит письмо менеджерам (HTML + текстовая версия,
   `Reply-To` = email клиента: можно ответить прямо из почты).
4. Клиенту уходит **автоответ** в фирменном стиле: подтверждение получения
   заявки, контакты компании и ссылка на сайт.
5. **Если SMTP не настроен или временно недоступен** — заявка не теряется:
   сохраняется в `backend/data/leads.jsonl` (одна строка = одна заявка),
   а клиент всё равно видит сообщение об успехе. Сбой пишется в лог.

## API

### `POST /api/leads`

Отправляет заявку на почту.

```json
{
  "name": "Иван",
  "email": "ivan@company.ru",
  "phone": "+7 (917) 345-67-89",
  "message": "Нужен корпоративный портал",
  "utm_source": "google",
  "utm_campaign": "brand"
}
```

`name`, `email`, `phone`, `message` — обязательные. Телефон проверяется
по формату: 10–15 цифр, допускаются `+`, пробелы, скобки и дефисы.

Ответы:

| Код | Ситуация |
| --- | --- |
| `200` | `{ ok: true, message }` — заявка принята (письмо ушло, сохранена в резерв или honeypot) |
| `400` | Ошибка валидации полей (Zod) |
| `403` | Источник запроса не разрешён (CORS) |
| `429` | Превышен лимит заявок с IP |

### `GET /api/health`

Health-check: `{ "status": "ok" }`.

## Защита

- **Zod-валидация** всех полей с ограничениями длины;
- **honeypot**-поле `company` против ботов (молчаливый ложный успех);
- **rate limit**: 10 заявок за 10 минут с одного IP;
- **CORS** только с адресов из `FRONTEND_URL`;
- **helmet** — безопасные HTTP-заголовки;
- тело запроса до 10 КБ; таймауты SMTP-подключения — 10 с;
- **экранирование HTML** в полях письма (защита от XSS в почтовом клиенте);
- SMTP-пароль существует только на сервере;
- ошибки наружу отдаются без внутренних деталей.

## Команды

```bash
npm run dev        # разработка с hot-reload (tsx watch)
npm run build      # компиляция TypeScript в dist/

```

## Переменные окружения (`.env`)

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `SMTP_HOST` | SMTP-сервер (smtp.yandex.ru, smtp.mail.ru, …) | — |
| `SMTP_PORT` | Порт SMTP | `465` |
| `SMTP_SECURE` | `true` — SSL (465), `false` — STARTTLS (587) | по порту |
| `SMTP_USER` | Логин ящика (обычно сам email) | — |
| `SMTP_PASS` | Пароль приложения | — |
| `MAIL_TO` | Куда присылать заявки | `info@algorithmos.ru` |
| `MAIL_FROM` | От чьего имени отправлять | = `SMTP_USER` |
| `SITE_URL` | Адрес сайта для ссылки в автоответе | `https://algorithmos.ru` |
| `PORT` | Порт API-сервера | `4000` |
| `FRONTEND_URL` | Разрешённые источники CORS (через запятую) | `http://localhost:9020` |

Без `SMTP_HOST`/`SMTP_USER`/`SMTP_PASS` сервис работает в резервном режиме:
заявки пишутся в `backend/data/leads.jsonl`.

### Настройка почты — примеры

**Яндекс 360 для бизнеса** (доменная почта info@algorithmos.ru):
`SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465`, пароль — «пароль приложения»
из раздела безопасности Яндекса.

**Mail.ru для бизнеса**: `SMTP_HOST=smtp.mail.ru`, `SMTP_PORT=465`,
пароль — «пароль для внешних приложений».

**Gmail**: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=465`, пароль приложения
(требуется включённая двухфакторная аутентификация).

## Деплой

Любой Node.js ≥ 18.18 рантайм: VPS (`pm2 start dist/index.js`), Docker,
Timeweb Cloud, Amvera и т.п. Перед бэкендом рекомендуется reverse-proxy
(nginx) с TLS.

```
server {
  listen 443 ssl;
  server_name api.algorithmos.ru;
  location / {
    proxy_pass http://127.0.0.1:4000;
    proxy_set_header X-Forwarded-For $remote_addr;
  }
}
```
